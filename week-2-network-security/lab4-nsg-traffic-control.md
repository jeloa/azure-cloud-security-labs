# Network Security Group (NSG) Configuration

## Objective
To control inbound network traffic using Azure Network Security Groups following a default-deny security model.

## Tools Used
- Azure Portal
- Network Security Groups (NSG)

## Steps Performed
1. Created a Network Security Group
2. Reviewed default inbound security rules
3. Added a custom rule to allow HTTP traffic
4. Verified rule priority and enforcement

## Security Analysis
- Default rules deny unsolicited inbound traffic
- Only required ports were explicitly allowed
- Reduced attack surface by limiting exposure

## Outcome
- Successfully restricted inbound traffic
- Improved understanding of cloud network security

## Security Concepts Learned
- Network segmentation
- Default deny
- Attack surface reduction
